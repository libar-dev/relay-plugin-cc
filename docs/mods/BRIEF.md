## Questions that must be answered with evidence
1. **Where will these Mods actually run for this user?** The user works mostly inside T3 Code,
   which drives Claude Code through the Claude Agent SDK / a non-terminal host, and also uses the
   terminal. The research doc's matrix says `claude -p` / Agent SDK gets hooks but "no
   interactive drawing". Establish exactly which Mod capabilities (events/hooks, commands,
   `immediate` commands, `$.ui.log`, panes, indicators, `$.session.send`, `$.process.run`,
   `$.store`/`$.state`) work in (a) terminal, (b) Desktop, (c) SDK-hosted sessions such as T3
   Code. This decides whether a UI-first plan is worth anything to this user, so be precise and
   cite the source or experiment.
2. Which relay responsibilities today (hooks in hooks.json: SessionStart, PreToolUse guard incl.
   the SubagentHandback matcher, SubagentStop guard, Stop review gate; the relay:job agent's
   Bash-mediated companion calls; status/result/steer/continue/cancel commands) could a Mod do
   better, and which must stay where they are? Note ordering and fail-open/fail-closed semantics.
3. What does the companion need to expose as a stable bridge for a Mod (JSON outputs, request
   ids, versioning, reconciling an action whose process timed out)? Check what `status --json`,
   `result --json`, `setup --json` emit today.
4. Which non-UI Mod features (events, typed classic hooks, session messaging, background
   process, commands that bypass a model turn) give value even where nothing can be drawn?
